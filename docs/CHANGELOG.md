## [2.5] - 2026-10-21

**這一版全部是「會直接令你打錯字」的修正。** 沒有新增功能，也沒有改動任何
鍵位習慣 —— 空白鍵、一頁 9 個、候選次序、`z` 的行為全部維持原樣。

### 修正（6 個會打錯字的 bug）

| # | 症狀 | 原因 |
|---|------|------|
| 1 | 打 `ab` 再按 `z`，**下一個字變成亂碼**（打出「　」） | `z` 當第三碼時被拒，但組字碼已先被清空 → 留下死碼 `z`，下個字母變成 `za` |
| 2 | 打 `hi` 按 `2` 選字，文件變成「**么2**」（數字漏進去） | 數字選字沒有被當成「要吞鍵」 |
| 3 | 打 `a`（日／曰）按空白鍵，**直接打出「日」** | 判斷用了「只有一頁」而不是「只有 1 個候選」 |
| 4 | `Ctrl+Shift+.` 想打 `>`，卻變成「**。**」 | 符號表有一張「按住 Shift」的版本，搶走了 `>` |
| 5 | 組字中按 `Ctrl+Shift+符號`，**組字碼殘留** | 上屏後沒有清乾淨，下一個字母會接上舊碼 |
| 6 | 暫停輸入法期間按住 Shift，恢復後 `Ctrl+Shift+.` 仍變成「。」 | Gate 失步：只信內部記憶，沒看實體鍵盤狀態 |

### 空白鍵規則（確認，非變更）

沿用微軟速成的實際行為，這一版把判斷寫得更精確：

- **全份候選只有 1 個** → 按空白直接上屏（例：`b` → 「月」）
- **2 個以上** → 空白鍵完全沒有作用（不上屏、不換頁；例：`a` → 日／曰）
- **有多頁** → 空白鍵下一頁；到尾頁再按**繞返第 1 頁**，永遠不會上屏

> 第 3 個 bug 就是這條規則的舊版寫錯：`a` 只有一頁但有兩個候選，
> 舊版用「只有一頁」判斷，於是擅自幫你選了「日」。

### 新增能力（內部）

- `HookResult.CommitPendingPass`：「送字但放行」（`ab` 按 `z` 用）
- 英文模式下 `Ctrl`+符號 完全透明（完全交回系統）
- `FullWidthPunct.IsMapped`：分辨 `Ctrl+Shift+符號` 與 `Ctrl+Shift+字母`

### 測試架構重寫（為什麼這一版值得信）

v2.4 的 147 項 `--selftest` 全過，卻同時存在 4 個會打錯字的 bug。根因是**測試自己
重寫了一套假的實作**，真正的外殼（回傳值 → 送字 → 吞鍵）從來沒被行使過。

這一版做了三件事：

1. `HookCallback` 外殼只做委派，本體移到 `OnHookMessage`
2. Win32 讀取與 `CallNextHookEx` 抽成可替換接縫（`Win` / `CallNext`）
3. 測試經 `InvokeHookCallback` 驅動**真正的外殼**，且每個情境各開新 hook

驗證方式是 **mutation testing**：故意把修正改壞，確認對應測試真的變紅。
10 個 mutation 全部都能令測試失敗，才算數。

| 測試 | v2.4 | v2.5 |
|------|------|------|
| `--selftest` | 147 | **152** |
| `--hooktest` | 46 | **177** |
| `--gametest` | 全部通過 | 全部通過 |

### 已知但刻意未修

- 聯想窗開著時 `Shift+1` 打不出 `!`（鍵位本身無法區分選字與打驚嘆號）
- NumPad 數字鍵未接（使用者沒有右邊 NumPad）
- 組字中 `Tab`/`Delete`/`Home`/`F5` 會先上屏首選（待實測微軟速成行為）
- 掛鉤回呼缺 `try/catch`、掛鉤執行緒寫硬碟、無 watchdog

詳見 [AGENTS.md](../AGENTS.md) 第五節。

## [2.4] - 2026-10-20

### 修正（4 個會打錯字的 bug）

| 症狀 | 原因 |
|------|------|
| 連打吞字：打 `abo` 之後「明」整個消失 | 字母分支沒有把待送文字送出去，被下一次選字覆蓋 |
| 尾頁上屏送錯字：翻到尾頁按 `Enter`，送出**第 1 頁**的字 | 用了「整份清單第 1 個」而非「當前頁第 1 個」 |
| 數字超界漏字：只有 2 個候選卻按 `5`，`5` 跑進文件 | 沒有處理「超出當頁」的情況 |
| 按 `z` 沒反應：中文模式下 `z` 被靜默吃掉 | 沒有檢查「這個字母是不是有效碼」 |

### 新增：`Ctrl` + 符號鍵 = 全形標點

跟微軟速成一樣，按住 `Ctrl` 再按符號鍵就是全形：

| 按鍵 | 輸出 | 按鍵 | 輸出 |
|------|------|------|------|
| `Ctrl` + `,` | `，` | `Ctrl` + `.` | `。` |
| `Ctrl` + `;` | `；` | `Ctrl` + `'` | `：` |
| `Ctrl` + `[` | `「` | `Ctrl` + `]` | `」` |
| `Ctrl` + `\` | `、` | `Ctrl` + `-` | `－` |
| `Ctrl` + `=` | `＝` | | |

`?` `!` `,` `.` 直接按仍然是**半形**，不會自動變全形。

### 其他

- 候選窗支援 **Per-Monitor DPI**，125% / 150% 縮放不會偏離插入點
- 檔案內容有版本號（`--version` 與檔案屬性一致，不再顯示 `0.0.0.0`）
- 新增 `--hooktest`：按鍵序列重播測試，把真實打字流程逐個跑一次
- 版本號只剩一個來源（`VERSION` 檔），不會再有「程式是 2.4 但 zip 名還寫 v2.3」
- 掛鉤內的日誌改成惰性求值，關閉日誌時完全不組字串（降低被系統移除掛鉤的風險）

## [2.3] - 2026-10-20

兩件「肌肉記憶」的事，改成跟 Windows 內建速成一致：

| 項目 | v2.2 | v2.3 |
|------|------|------|
| 聯想字選字 | 直接按 `1`–`9` | **`Shift` + `1`–`9`**（直接按 = 打數字） |
| 空白鍵到尾頁 | 再按 = 上屏第 1 頁第 1 個字 | **再按 = 繞返第 1 頁**，循環翻頁 |

### 為什麼空白鍵不再「到尾頁就上屏」

微軟速成用家掃候選字時，手指會一直按空白鍵。掃到尾頁那一下如果就上屏，
用家會在意想不到的情況下打出一個字（而且是錯的字）。
所以空白鍵**只負責翻頁**：到尾頁再按就是繞返第 1 頁，永遠不會偷偷上屏。
要上屏就按數字鍵（或用 `Enter`／標點，維持原本的「先上屏首選」行為）。

順帶修正了一個舊 bug：v2.2 在尾頁按空白，上屏的是**第 1 頁**的第 1 個字，
而不是畫面正看著的那一頁的候選字。

### 聯想字 Shift+數字可關閉

右鍵系統匣 → **聯想字** → 勾選／取消 **「Shift + 數字鍵選聯想字」**。
取消之後就回復 v2.2 的直接數字選字。
（聯想字關掉時這一項會變灰，因為已經沒有意義。）

## [2.2] - 2026-10-18

聯想字和「記錄習慣」變成**兩個獨立開關**：

| 聯想字 | 記錄用字習慣 | 效果 |
|--------|-------------|------|
| ✅ 開 | ✅ 開（預設） | 有聯想，而且越用越貼你的習慣 |
| ✅ 開 | ❌ 關 | **仍然有聯想，但只用出廠詞表**，不會再學新東西 |
| ❌ 關 | — | 完全不出聯想窗 |

右鍵系統匣 → **聯想字** → 勾選／取消 **「記錄用字習慣（常用的組合排更前）」**。

> 關掉學習**不會刪除**已學到的記憶 —— 之前學的仍然照舊排序，只是不再新增。
> 想真正清走就用「清空聯想字記憶」。
> 聯想字關掉時，「記錄習慣」和「清空」會變灰（因為已經沒有意義）。

## [2.1] - 2026-10-18

新增**聯想字**：打完一個中文字，自動列出「最可能接住落去」的字。

```
聯想  你
 1   2   3   4   5   6   7   8   9
好  嗎  係  唔  的  有  會  想  了
```

> **本版是直接按 `1`–`9` 選聯想字**，v2.3 起改成 `Shift` + `1`–`9`。

### 同 Windows 內建聯想字的分別：**佢會學你**

Windows 的聯想字是固定的。本專案的聯想字會**記錄你的用字習慣**：

| 情況 | 結果 |
|------|------|
| 你打完「你」之後經常接「係」 | 打多幾次，「係」由第 3 位爬到第 1 位 |
| 之後改用「嗎」多啲 | 「嗎」又會爬到第一 |
| 你未用過的組合 | 保留出廠預設次序 |

排序規則：**學過的排前（次數越多越前），未學過的保留出廠次序。**

### 聯想窗操作

| 按鍵 | 功能 |
|------|------|
| `1`–`9` | 選聯想字（v2.1／v2.2 行為） |
| `空白鍵` / `Esc` | 收起聯想窗（不上屏任何東西） |
| 直接打速成碼 | 照常打字（聯想窗自動收起） |

聯想窗 **6 秒**無操作會自動收起。只建議單一中文字；標點、英文、數字都不會學。

### 清空聯想字記憶

右鍵系統匣圖示 → **聯想字** → **清空聯想字記憶…**

- 會確認一次（無法復原）
- 清空後回復**出廠預設**聯想詞表，之後重新學習
- **速成候選字次序完全不受影響**

記憶存在 `%APPDATA%\QuickIME\assoc.txt`（純文字，可自行檢視或編輯）；
刪掉該檔等同清空。不想用聯想字：右鍵 → **聯想字** → 取消勾選即可。

## [2.0] - 2026-10-18

v1.0 有一個對打機的人很致命的設計：**單按任何一邊 Shift 都會切換中英**。
長按左 Shift 跑步，一放開就變成英文，角色突然不受控。

v2.0 全部改掉：

| 問題 | v1.0 | v2.0 |
|------|------|------|
| 長按 Shift 跑步 | 放開就切英文 ❌ | 只有**右 Shift** 單按才切換 ✅ |
| Shift + WASD | 可能誤切換 ❌ | 期間按過其他鍵就**一律不切換** ✅ |
| 長按不放 | 仍會切換 ❌ | 超過 **0.7 秒**就當長按，不切換 ✅ |
| 長按期間打中文 | WASD 被吃掉 ❌ | **完全不組字**，鍵盤原樣給遊戲 ✅ |
| 誤按 `Ctrl+空白` | 可能轉全形 ❌ | **預設攔死**，完全冇反應 ✅ |
| 打機時睇狀態 | 要讀 tooltip ❌ | 圖示**變色**：藍＝中／灰＝英 ✅ |
| AppData 被鎖 | **整個程式開唔到** ❌ | 自動退回 exe 同目錄 ✅ |

### 打機用：左右 Shift 分開設定

- **預設只有「右 Shift」單按才切換中／英**，左 Shift 完全留給遊戲
- 按住 Shift 期間再按其他鍵（WASD／方向鍵）→ **一律當長按，不切換**
- 按住超過 **0.7 秒**才放開 → **一律當長按，不切換**
- 按住 Shift 期間**完全不組字**，鍵盤原樣傳給遊戲

想改的話：右鍵系統匣圖示 → **設定**。

```text
中英切換鍵（單按 Shift）
  ☐ 左邊 Shift 單按切換中／英
  ☑ 右邊 Shift 單按切換中／英
──────────────────────
☑ 攔住 Ctrl+空白（唔會轉全形符號）
──────────────────────
  符號：直接按半形，Ctrl+符號鍵打全形
```

兩邊都不勾 = 完全關閉 Shift 切換（只能按系統匣圖示切換）。
設定會存到 `%APPDATA%\QuickIME\settings.ini`，刪掉即回覆預設值。

### 系統匣圖示會變色（一眼看狀態）

| 圖示 | 狀態 |
|------|------|
| 藍色「**速**」 | 中文模式（速成） |
| 灰色「**英**」 | 英文模式 |
| 深灰「**速**」 | 已暫停 |

打機時不用看 tooltip，用眼角瞄一眼顏色就知道現在會不會打出中文。

## [1.0] - 2026-10-18

首個版本。

- 速成（首碼 + 尾碼）查字，21,701 字，含香港增補字符集
- 單碼輸入（`a` → 日、`o` → 人）
- 候選字視窗，跟隨文字插入點
- 數字鍵 1–9 選字（一頁 9 個）
- 連打（打滿兩碼再打字母會立刻上屏首選）
- 免安裝、單一執行檔、可放 USB 帶著走
- 不寫註冊表、不裝驅動、不改系統設定、不經剪貼簿
